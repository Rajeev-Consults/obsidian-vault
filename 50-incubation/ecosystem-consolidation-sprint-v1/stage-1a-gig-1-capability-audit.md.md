# Stage 1A — Gig 1 Capability & Evidence Audit

> **Parent:** [[ecosystem-consolidation-sprint-v1]]  
> **Status:** 🟡 Incubating  
> **Gig:** Fiverr Gig 1 — Process Mapping  
> **Objective:** Establish what exists, what is missing, and what must be consolidated before building further.

---

# 1. Stage Objective

Audit the JayaSwara ecosystem **from the perspective of Gig 1**, rather than randomly, folder-by-folder or project-by-project.

The central question is:

> **Could the current ecosystem credibly support delivery of Gig 1 if a client ordered it tomorrow?**

The audit must identify:

- Completed work
    
- Partial work
    
- Duplicated work
    
- Orphaned work
    
- Missing capability
    
- Existing evidence
    
- Missing evidence
    
- Knowledge gaps
    
- Delivery gaps

### Disposition codes

- **KEEP** — already useful
    
- **COMPLETE** — incomplete but valuable
    
- **CONSOLIDATE** — duplicate/scattered
    
- **DEFER** — useful but not V1-critical
    
- **ARCHIVE** — obsolete
    
- **MISSING** — required but absent

# 9. Capability → Evidence Audit

For each primary capability assess six layers.

## Layer 3 — Toolkit

- Do templates exist?
    
- Do checklists exist?
    
- Do frameworks exist?
    

## Layer 4 — Practice

- Have we actually applied the capability?
    

## Layer 5 — Evidence

- Can we demonstrate the capability?
    

## Layer 6 — Delivery

- Could we execute the capability for a paying client?

# 11. EKAR / Knowledge Audit

The book library is treated as a **knowledge resource**, not as a reading obligation.

### First determine the gaps

- Identify knowledge gaps
    
- Identify capability gaps
    
- Identify methodological gaps
    
- Identify evidence gaps
    

### Then use EKAR

- Search EKAR for relevant material
    
- Identify high-value resources
    
- Prioritize resources
    
- Create targeted reading list
    
- Record why each resource matters
    

### Reading rule
